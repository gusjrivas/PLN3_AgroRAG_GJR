# ADR-002: SDD con OpenSpec y Engram de desarrollo

Estado: propuesto. Fecha: 21/10/2026. Responsable: coordinador; revisión humana: Gustavo Julián Rivas.

## Contexto

Los agentes necesitan continuidad y un contrato auditable para la cátedra.

## Decisión propuesta

OpenSpec spec-driven para cambios; ADR para decisiones; Engram local para memoria contextual. Git es la fuente de verdad. Inicializar memoria del proyecto después del bootstrap del repo y antes de implementar corpus. No requerir Engram para ejecutar el producto.

## Alternativas

Sólo chat/memoria: no versiona comportamiento. Sólo lista de tareas: carece de escenarios. Dos frameworks SDD simultáneos: duplica la fuente de verdad.

## Consecuencias y límites

Costo de mantener docs acotadas por cambio; no exigir cloud ni instalación Engram a los evaluadores. Recuperación entre sesiones debe probarse.

## Verificación y condición de revisión

Cambio OpenSpec validado; memoria recuperada tras reinicio; runtime ejecutable sin Engram. Conflicto Git/memoria se resuelve revisando Git.

Cambio relacionado: `01-engram`. Si las pruebas o restricciones invalidan la decisión, registrar evidencia y redactar ADR sucesor antes de modificar el contrato.
