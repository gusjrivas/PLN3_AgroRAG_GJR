# ADR-016: metadata curada con compatibilidad y priorización comunes

Estado: propuesto y autorizado para implementación incremental. Fecha: 07/11/2026. Responsable:
coordinador; revisión humana del alcance: Gustavo Julián Rivas.

## Contexto

La profesora recomendó asociar cultivo, etapa de desarrollo, región y fuente a los chunks y usar esos
datos en retrieval. El producto ya conserva procedencia y cultivo, pero no propaga etapa/región al
retriever ni aplica una política común entre BM25 y Pinecone. La explicación docente posterior no
llegó; el usuario autorizó registrar un plan técnico acotado sin atribuir esa especificación a la
profesora.

## Decisión

Extender el manifiesto curado y `Evidence` con tipo de fuente, etapas, regiones de aplicabilidad y
alcance general/específico/desconocido. Sólo se admiten valores respaldados por la fuente; no se
infieren mediante LLM, institución, nombre local o metadata inestable del sistema de archivos.

Introducir `RetrievalFilters` estructurado y una política pura compartida que clasifique candidatos
como exactos, generales, desconocidos o incompatibles. Cultivo contradictorio se excluye. Etapa y
región priorizan inicialmente, porque volverlas filtros estrictos sobre 27 fragmentos puede degradar
recall. Se conserva el orden del proveedor dentro de cada clase, seguido de diversidad y presupuesto.

BM25 continúa sin dependencias semánticas. Pinecone almacena metadata mínima sin texto; el catálogo
local resuelve la evidencia autoritativa. Cambiar metadata crea corpus, IDs, snapshot y namespace
nuevos. La API propaga filtros explícitos y los incluye en caché. La variante se compara contra el
baseline y no cambia el default sin evidencia y decisión posterior.

## Alternativas

- Filtros estrictos para todos los campos: más precisión aparente, riesgo alto de perder evidencia.
- Concatenar tags al texto: simple, pero contamina BM25/embeddings y vuelve opaca la política.
- Inferir tags con LLM: reduce curación, pero introduce clasificación no trazable.
- Esperar indefinidamente una explicación docente: evita decidir, pero deja una mejora viable sin
  evaluación. Se prefiere el cambio acotado y reversible autorizado por el usuario.

## Consecuencias y límites

Habrá migración de IDs/qrels y reindexado, siempre conservando la versión anterior. La taxonomía
inicial es deliberadamente pequeña y puede dejar `unknown`. La evaluación puede no mostrar mejora;
ese resultado se informa. Metadata orienta aplicabilidad, pero no reemplaza evidencia textual ni
autoriza recomendaciones de riego sin contexto suficiente.

## Verificación y condición de revisión

Escenarios META-01..05, evidencia TDD por corte, reconstrucción determinista, paridad de política,
caché aislada, payload remoto seguro, rollback y benchmark comparativo. Revisar esta decisión si el
corpus crece lo suficiente para filtros estrictos, si la profesora aporta otra taxonomía o si la
evaluación muestra pérdida significativa de recall.
