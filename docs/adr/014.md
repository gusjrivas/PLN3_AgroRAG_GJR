# ADR-014: proveedor generativo OpenAI opcional y explícito

Estado: aplicado al corte `feat/openai-provider` por pedido del usuario. Fecha: 24/10/2026.
Revisión: misma sesión; revisión humana pendiente.

## Contexto

Ollama permitió comprobar el flujo investigador/verificador, pero el equipo local no dispone de
recursos holgados y la inferencia CPU se aproxima al deadline. El puerto `Model` de aplicación ya
permite sustituir el adaptador sin acoplar dominio, UI ni orquestación a un proveedor.

## Decisión

Agregar un adaptador OpenAI Responses API seleccionable con `AGRO_MODEL_PROVIDER=openai`. Requiere
`OPENAI_API_KEY` y `AGRO_OPENAI_MODEL`; una configuración incompleta deja generación en estado no
ready. Ollama continúa disponible con selección explícita. No hay fallback silencioso entre
proveedores, porque cambiarlo altera costo, privacidad, latencia y reproducibilidad.

Ambos adaptadores comparten prompts y JSON Schema. OpenAI usa Structured Outputs estricto,
`store=false`, presupuesto y deadline existentes. La key es `SecretStr`, sólo vive en backend y no
se incluye en prompts, UI, respuestas ni logs. Readiness consulta metadata del modelo sin generar
texto.

El adaptador fija `temperature=0` para reducir variación de muestreo en decisiones documentales.
Esto mejora el control experimental, pero no garantiza determinismo absoluto: cambios del modelo o
de la infraestructura del proveedor todavía pueden alterar una salida. Los prompts distinguen una
pregunta factual respondible por la evidencia de una consulta que carece de referente o contexto
imprescindible.

## Consecuencias y límites

Con OpenAI, preguntas, contexto y pasajes recuperados salen del equipo hacia la API. Sólo usar
fuentes públicas admitidas por el catálogo y no ingresar datos sensibles. La configuración de
`store=false` se envía en cada respuesta, pero este proyecto no formula garantías adicionales de
retención fuera del contrato vigente del proveedor.

Las pruebas automáticas interceptan HTTP y no consumen créditos. Una integración real queda
pendiente hasta disponer de key, acceso al modelo y autorización de costo. Registrar modelo exacto
y repetir evaluación antes de comparar resultados con Ollama.

Esta decisión amplía ADR-012: Ollama deja de ser la única implementación real opcional, sin cambiar
el puerto de aplicación ni el contrato de evidencia.
