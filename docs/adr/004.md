# ADR-004: Frontend Python Streamlit mediante HTTP

Estado: propuesto. Fecha: 21/10/2026. Responsable: coordinador; revisión humana: Gustavo Julián Rivas.

## Contexto

Se necesita una demostración clara sin introducir otro stack del producto.

## Decisión propuesta

Streamlit en proceso separado consume FastAPI mediante httpx. Modelos de vista y cliente inyectable, estado por sesión, validación local de forma y validación canónica backend. AppTest para estados y Playwright Python para E2E.

## Alternativas

Streamlit con acceso directo al RAG: acopla UI y negocio. React/TypeScript: viable, pero agrega stack que no hace falta al alcance Python. Sólo Swagger: útil como diagnóstico, insuficiente para la demo propuesta.

## Consecuencias y límites

Streamlit reruns exigen controlar duplicación de consultas. Accesibilidad y layout requieren revisión visual adicional. Clave reader sólo en servidor UI.

## Verificación y condición de revisión

Rerun no factura una segunda consulta; dos sesiones no comparten contexto; UI muestra error operativo separado de abstención y permite inspeccionar fuente.
