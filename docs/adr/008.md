# ADR-008: TDD obligatorio y pruebas por contrato

Estado: propuesto. Fecha: 21/10/2026. Responsable: coordinador; revisión humana: Gustavo Julián Rivas.

## Contexto

El usuario pide TDD para todo el desarrollo, incluidas capas backend/frontend/arquitectura.

## Decisión propuesta

RED→GREEN→REFACTOR documentado por tarea. pytest y fakes en lógica, pruebas de contrato HTTP, AppTest para UI, Playwright Python E2E y tests de límites de importación. Pruebas de caracterización antes de adaptar código docente. CI determinista sin proveedores pagos.

## Alternativas

Tests al final: incumplen la instrucción. Sólo cobertura: no acredita proceso ni corrección. Sólo tests con LLM real: inestables, lentos y difíciles de diagnosticar.

## Consecuencias y límites

Registrar evidencia real añade disciplina. Metas propuestas de branch coverage 85% global/90% core; escenarios críticos obligatorios aun con cobertura alta. Revisar configuración infra con smoke tests y documentación con validación estructural.

## Verificación y condición de revisión

Cada PR funcional enlaza test fallido previo y verde posterior. No falsear fallos por configuración como RED funcional. Evaluación científica separada de tests mock.

Cambio relacionado: `00-foundation`. Si las pruebas o restricciones invalidan la decisión, registrar evidencia y redactar ADR sucesor antes de modificar el contrato.
